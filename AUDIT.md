# XP Newtab audit and modernization

Date: September 5, 2026

## Scope

Reviewed every application source module, saved-data flows, browser manifest, build configuration, dependency tree, existing tests, CI, and all GitHub issues in [Etesam913/xp-newtab](https://github.com/Etesam913/xp-newtab/issues). The working copy was clean before this work. Changes preserve the Windows desktop design, existing localStorage keys, window/component IDs, and extension identity. No release has been published and no issues have been closed.

The new YouTube host permission is restricted to `https://www.youtube.com/*`. Header changes are further limited by the extension's own initiator and subframe URL. No global request rewriting, third-party proxy, remote executable code, or removal of frame restrictions is used. Browser updates may ask users to accept this additional permission.

References: [YouTube API client identity and referrer format](https://developers.google.com/youtube/terms/required-minimum-functionality#embedded-player-api-client-identity), [Chrome declarativeNetRequest](https://developer.chrome.com/docs/extensions/reference/api/declarativeNetRequest), [Firefox session rules](https://developer.mozilla.org/en-US/docs/Mozilla/Add-ons/WebExtensions/API/declarativeNetRequest/updateSessionRules).

Direct dependencies are pinned to the stable versions verified from npm during this audit. The lockfile was regenerated without forcing incompatible peer dependencies. Its package entries dropped from 1,544 to 166 (including platform-specific optional packages). The final npm advisory audit reports zero known vulnerabilities.

The note editor, kanban board, and individual OS styles load on demand. Unused themes and editor code no longer need to load on every empty new tab. No generated JavaScript chunk exceeds Vite's default 500KB warning threshold.

The published XP.css and 98.css contain legacy CSS syntax rejected by Lightning CSS's minifier. CSS minification is disabled explicitly; Vite still processes and bundles their font URLs. These upstream stylesheets are already minified. The vendor packages themselves are not patched.

## Additional correctness improvements

- Register and remove the same edit-shortcut listener. Support Ctrl+E and Cmd+E and ignore key-repeat events.
- Save notes on content changes instead of waiting for focus/blur. Synchronize note content and desktop changes across open new tabs.
- Use the latest store state for component edits and clone nested arrays rather than mutating previous state. Keep unaffected components when closely spaced updates occur.
- Use stable persisted IDs as React keys so deleting/reordering windows does not transfer local editor state to another item.
- Fix the missing Windows 98 menu callbacks for creating windows/icons, and consistently close that menu after creation.
- Handle absent drag targets, clear canceled drag state, restore kanban contents on canceled cross-column drags, and use matching item IDs in sortable contexts. Attach sortable measurement refs to whole items and activation refs to handles.
- Validate saved settings, icons, windows and components at runtime with Valibot. Recover known legacy asset URLs, preserve empty desktops, and back up malformed data before replacement. Failed backups prevent overwriting the original.
- Keep storage errors visible until the failing data can be saved, even when another kind of data saves successfully.
- Isolate damaged component content with an error boundary, retaining its original data and keeping the desktop available.
- Replace unavailable placeholder images, remove leaking image-focus listeners and `javascript:` image links, use unique component radio/search IDs, and allow window title-bar buttons to work without a preliminary focus click.

Recovery copies are retained as `<storage-key>.recovery.<timestamp>` in the extension's localStorage. They can be exported through browser developer tools. Recovery intentionally does not silently discard the original value when storage is full or unavailable.

## Verification

- Strict TypeScript and production Vite build: passed.
- Unit tests: 31 passed.
- Chromium browser regressions: 12 passed, including offline themes, Windows 98 actions, window drag/rename/minimize/maximize/delete, immediate formatted-note persistence, image controls, YouTube URL validation, corrupt-data recovery, kanban cancellation, icon positioning/navigation, damaged-note isolation, cross-tab synchronization, and packaged-extension startup.
- Opt-in live YouTube extension request: passed; correct Referer and HTTP 200. This verifies the embed request, not uninterrupted playback of every video. Video-owner restrictions, sign-in requirements and third-party blockers remain controlled by YouTube/the browser.
- Mozilla `web-ext` 10.6.0 lint: zero errors; five warnings described below.
- npm audit: zero known vulnerabilities.
- Firefox browser tests: attempted, but the bundled Firefox 155 test browser exits before opening a page with `Could not find profile folder` on this macOS 27.0 developer-beta host. A retry with a direct `/private/tmp` profile path failed the same way. The same suite is configured for Firefox in Linux CI, but that remote run has not been observed.

## Release and follow-up items

1. **Firefox validation:** run the configured Firefox suite on a supported host/CI and load the extension in Firefox to verify the referrer rule there. Chromium extension behavior is verified; Firefox extension behavior is not yet confirmed.
2. **Store metadata:** decide and document the Firefox data-collection declaration before publishing. The linter warns that `browser_specific_settings.gecko.data_collection_permissions` is absent. This is an existing extension, for which adoption is not yet mandatory according to [Mozilla's current guidance](https://extensionworkshop.com/documentation/develop/firefox-builtin-data-consent/). Search terms, custom destination/image requests and YouTube embeds need to be considered; claiming `none` without that review would be misleading. Release versions were not bumped.
3. **Vendor lint review:** four `innerHTML` warnings come from React DOM's internal `dangerouslySetInnerHTML` handling and Prism's highlighting helpers bundled through Lexical. Application code does not use `innerHTML` or `dangerouslySetInnerHTML`; the manifest continues to disallow eval and remote scripts. Preserve these source attributions for store review rather than suppressing the linter globally.
4. **Larger desktops:** localStorage still serializes the full window collection on each content edit. Item-level IndexedDB persistence would be a separate data migration if very large notes/boards become a performance problem. Ordinary cross-tab updates synchronize; simultaneous writes to the same key are still last-write-wins.
5. **Accessibility and recovery UI:** a complete keyboard/focus-trap audit and an in-app backup import/export interface remain useful follow-up features. Basic shortcut, start-button, icon, search, iframe, and editor labeling were improved here.

No published-site deployment, extension-store submission, GitHub issue mutation, or release tagging was performed.
